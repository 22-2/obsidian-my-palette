# アイデア: 表形式の結果と、モードごとの並び順

計画ではなく、試したいことと、使えそうな既存のコードのメモ。実装するときは、別途計画を立てる。

## 1. Everything の結果を Everything 本体のような表にする

Everything 本体の結果一覧は、`名前`、`サイズ`、`フォルダ`、`更新日時`、`作成日時` の列が並び、列の見出しを押すと並べ替わる。Everything のモード(「Search Vault Notes」「Search All Files in Vault」)の結果を、同じような表で見せる。

- 列の候補: `Name`、`Folder`、`Modified`、`Created`、`Size`。`Size` は既定で隠す。
- 列の表示・非表示は、見出しの右クリックメニューで切り替える。
- 見出しを押すと並べ替わる(昇順 → 降順 → 解除)。

### 使える既存のコード

| 既存のもの                                                                                                     | 場所                                            | 使い道                                                                                                                                                 |
| -------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| tanstack の表のモデル(並べ替え、列の順番、列の非表示)                                                          | `src/palette/table/paletteTableModel.ts`        | 列の定義を足せばそのまま使える。保存する状態(`sorting`、`columnOrder`、`hiddenColumns`)の形と、壊れた状態を捨てる正規化もある                          |
| 表の描画と操作(見出しで並べ替え、ドラッグで列の入れ替え、右クリックで列の表示切り替え、列幅、50件ごとのページ) | `src/palette/table/PaletteTableControls.ts`     | テーブルビュー(`PaletteTableView`)で動いている。`SuggestionPanel` に結果の描き方(`setResultsLayout`)を差し込む作りなので、モーダルにも載せられる見込み |
| 結果の描き方の差し込み口                                                                                       | `SuggestionPanel.setResultsLayout`              | 行の選択・キー操作・右クリックはパネル側が持つので、表にしても今の操作がそのまま効く                                                                   |
| Everything の問い合わせ                                                                                        | `src/search/everything/EverythingHttpClient.ts` | 今は `path_column` と `attributes_column` だけを頼んでいる。列を足すのはパラメーターを足すだけ                                                         |

### Everything の HTTP Server でできること(要確認)

Everything の HTTP Server は、問い合わせのパラメーターで列と並び順を指定できる(実装前に Everything 1.5a で確かめる)。

- 列: `size_column=1`、`date_modified_column=1`、`date_created_column=1`
- 並び順: `sort=name|path|size|date_modified|date_created`、`ascending=1|0`
- 日時は Windows の FILETIME(1601年からの100ナノ秒単位)で返る見込みなので、変換が要る。

大事な点: 今は最大件数(既定100件)で切ってから受け取るので、受け取ったあとで並べ替えても「本当に新しい100件」にはならない。Everything の表で見出しを押したときは、表の中で並べ替えるのではなく、`sort` を付けて問い合わせ直す。ほかのモードの表は、今のテーブルビューと同じく表の中で並べ替える。

## 2. モーダルのパレットに表を埋め込む(実験)

サイドバー・センターのテーブルビューにある表を、モーダルのパレットでも使えるようにする。

- モードごとに「リスト」か「表」かを選べるようにする。最初は Everything のモードだけ表を既定にして試す。
- 列の表示・非表示、並べ替え、列の順番は、モードごとに覚える(テーブルビューのペインごとの状態と同じ形)。
- モーダルの幅(今は700px程度)では列が窮屈なので、表のときだけ幅を広げる。

### 使える既存のコードと、足りないもの

- `PaletteTableControls` は `SuggestionPanel` と `App` を受け取って動くので、仕組みの上ではモーダルの中のパネルにも付けられる。
- `BaseSuggestModal` はパネルを外に見せていない(`private panel`)。表を付けるための入口を足す必要がある。
- ページ送り(50件ごと)は、モーダルでも要るかを試して決める(モーダルは今も50件まで)。
- 表のときも、↑↓、Enter、右クリック、中クリック、`Alt+H` が今と同じに動くかを、撮影タスクとE2Eで確かめる。

## 3. リンクのモードの並び順

Outgoing Links / Backlinks は、空入力ではパス順、入力時はあいまい検索のスコア順で並ぶ。ファイル検索の並び順(最近開いた順、更新順、`@prior`、優先度を下げるフォルダー)を使えると便利な場面がある。

案A: モードの設定にスイッチを1つ置く。

- `Note order`(今の並び)と `Same as Files`(ファイル検索の空入力の並び順)を切り替える。
- 入力時はあいまい検索のスコアを優先し、同点の並びにだけファイル検索の並び順を使う。

案B: 2. の表をリンクのモードでも使えるようにし、`Modified` や `prior` の見出しを押してその場で並べ替える。

- 設定を増やさずに済む。いつも同じ並びにしたいなら案A、その場で見比べたいなら案B。

### 使える既存のコード

- `sortFilesWithoutQuery`(`src/search/file/fileSorting.ts`)は、`path`、`basename`、`aliases`、`mtime`、`prior` を持つ要素なら並べられる。リンクの結果は `TFile` を持っているので、メタデータキャッシュから要素を作れば使える。
- 最近開いた順と使用回数(`recent`、`usageScores`)は、`FileProvider` が持っているものを渡す必要がある。
- 「ファイル名の前方一致」などの一致系の項目は、空入力では元から外れる(`filterNoQueryPriorities`)ので、リンクのモードでも問題にならない。

## ほかのモードに並び順の設定を広げない理由

| モード        | 今の並び                    | ファイル検索の並び順を当てはめると                                        |
| ------------- | --------------------------- | ------------------------------------------------------------------------- |
| Bookmarks     | 登録した順                  | 自分で並べた順が崩れる                                                    |
| Related Notes | 似ている度合いの順          | 似ている度合いに意味があるので壊れる                                      |
| Switch Tab    | タブの並び順                | 意味がない                                                                |
| Run Command   | 最近使った順 + あいまい検索 | 別の仕組みで、項目が当てはまらない                                        |
| Everything    | Everything が返した順       | 最大件数で切ったあとなので、上位が正しくならない(1. の `sort` で解決する) |
