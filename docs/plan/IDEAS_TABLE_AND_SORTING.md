# ファイル関連の並べ替えと表形式の計画

ファイル関連の検索結果を、キーボードだけで並べ替えられるようにする。並べ替えと表形式の表示は別の機能として扱い、まずリストでも使える並べ替えを実装する。Everything の表とモーダルの表は後の段階で検討する。

**初期実装済み:** `Ctrl+,` の専用メニュー、Vault ファイル検索と発リンク・被リンクの単一条件ソート、モードごとのセッション内状態、テーブルビューの既存列ソートとの接続。設定画面からショートカットを変更・無効化できる。

## 操作

- 専用の「並べ替え」メニューを設け、既定の `Ctrl+,` で開く。既存のオプションメニューは `Ctrl+O` のままにする。
- ショートカットは既存の設定画面で変更・無効化できるようにする。Obsidian 側の割り当てとの競合と、モーダル・サイドバー・テーブルビューでの優先順位を実機で確認する。
- 対象モードでは、↑↓で項目を選び、Enter で適用する。同じ項目を選ぶと昇順・降順を切り替える。Escape で閉じ、検索入力にフォーカスを戻す。
- 「標準の順序」で、そのモード本来の並びに戻す。検索入力中は、明示した並べ替えを検索スコアより優先する。
- 現在の項目と方向をメニューに表示し、適用中の並びが分かるようにする。項目の初期方向は、名前・パスは昇順、日時・`prior` は降順を候補とする。
- 対象外のモードではショートカットを消費せず、メニューも開かない。

初期実装のメニューは単一条件とする。項目を選ぶと、それまでの並べ替え条件を置き換える。既存テーブルの見出しは複数条件を保持するため、メニューで選んだときの置き換え、見出しで変更したときのメニュー表示、標準への復帰を一貫させる。複数条件をメニューで編集する機能は、必要性を確かめてから検討する。

## 対象と項目

まず Vault 内のファイル検索と Outgoing Links / Backlinks を対象にする。対象ごとに実際に取得できる項目だけを出す。

| 項目               | 内容と確認事項                                                                                                          |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| 名前、パス         | 比較方法と同値の場合の順序を既存の並べ替えに合わせる。                                                                  |
| 更新日時、作成日時 | `TFile` の情報を利用する。作成日時の提供範囲は実装時に確認する。                                                        |
| 最近開いた順       | Obsidian の履歴順を使う。日時を持っているとは限らないため、日時の表示は前提にしない。履歴にないファイルの位置も決める。 |
| `prior`            | frontmatter の数値を使う。値がないファイルの位置を昇順・降順の両方で決める。                                            |

標準の順序は既存の provider の結果を保つ。特にリンク系は空入力ではパス順、入力時は検索スコア順とする。ファイル検索は既存の空入力・入力時それぞれの優先順位設定を維持する。

Bookmarks の登録順、Related Notes の類似度順、Switch Tab のタブ順、Run Command の履歴・検索順には、ファイル用の並び替えを一律に適用しない。必要性があれば個別に検討する。

## メニューの共通化

既存の `PaletteMenu` が持つキー操作や絞り込みを再利用する。オプションメニューと並べ替えメニューで、表示位置、開いているメニューの管理、キーボードで開いたときの選択、終了時のフォーカス復帰を共通化する。項目の組み立てと動作は各メニューに残す。基底クラスを作るか、小さな関数・コントローラーにするかは既存の重複を確認して決める。

`PaletteHistoryControls` のオプションメニュー、`PaletteMenu`、`SuggestionPanel` と各表示面のショートカット処理を調べ、モーダル・サイドバー・テーブルビューで同じ操作ができるようにする。入力中の IME、他のショートカット、選択行やスクロール位置にも注意する。

## 状態と表示

- 並べ替えはモードごとに分け、モードを移動しても別のモードの条件が混ざらないようにする。
- 初期実装では、モーダル・サイドバー・テーブルそれぞれの検索セッション内でモードごとに保持する。閉じた後や Obsidian 再起動後への保存はしない。永続化は利用状況を見て別途決める。
- リスト・表で同じ条件を使う。並べ替え後も可能な限り選択中の結果を維持する。
- 値の欠損、同値の順序、検索結果の更新・削除、非同期検索の結果が入れ替わる場合を確認する。
- 並べ替えは表示件数の制限より前に行う。共通の `SuggestionPanel` は表示時に件数を制限しているため、provider 側にも先行する制限がないか対象ごとに確認する。

## Everything は別段階

Everything は最大件数で取得結果が制限されるため、取得後に並べ替えるだけでは全結果の上位を選べない。検索先に並び順を指定して問い合わせ直し、古い応答が新しい条件を上書きしないようにする。標準の順序への復帰や、検索中の表示も決める。

HTTP Server の `sort=name|path|size|date_modified|date_created`、`ascending=1|0`、`size_column=1`、`date_modified_column=1`、`date_created_column=1` は候補であり、Everything 1.5a で実際のパラメーターと日時形式を確認する。ES クライアントの指定方法と取得可能な列も別途確認し、対応できない条件を同じように見せない。

## 表形式は別段階

Everything の表には Name、Folder、Modified、Created、Size を候補とし、Size は既定で隠す。見出しでの並べ替えは上記の再検索につなぐ。列の表示・非表示や並び順の変更は既存テーブルを参考にする。

モーダルにも `PaletteTableControls` と `SuggestionPanel.setResultsLayout` を使えるか試す。パネルへの入口、モーダル幅、表示件数、列の状態保存、↑↓・Enter・右クリック・中クリック・`Alt+H` の動作を確認する。リンク系の表には Name、Path、Modified、`prior`、Opened、Line を候補とするが、Opened は履歴順を日時として表示できるか確認してから決める。

## 実装順と検証

1. 対象・項目、標準順、セッション単位の保存、対象外モードでメニューを出さない方針を決めた。
2. メニューの共通部分とショートカットを整え、Vault ファイル検索とリンク系に単一条件の並べ替えを追加した。
3. 表の見出しとメニューの状態を連動させる。初期実装はテーブルビューで既存の Name、Path、Modified、`prior` の列だけをメニューに出す。Created と Recently opened はリスト表示で利用でき、テーブルビューでは列モデルへの追加を別途検討する。検索・件数制限・欠損値・状態復元を単体テストし、各表示面でキー操作とフォーカスを E2E で確認する。
4. Everything の HTTP / ES の対応を調べ、検索先での並べ替えと再検索を実装する。
5. 必要性を確認したうえで、Everything の表とモーダルの表を検討する。

コストの目安は、メニューと Vault / リンク系が中程度、Everything とモーダルへの表の追加がそれぞれ大きめ。実装箇所と検証範囲の相対評価であり、日数の見積もりではない。
